# Руководство пользователя Sysadmin Anywhere

## 1. Назначение сервиса
Sysadmin Anywhere — веб-интерфейс для администрирования Active Directory и связанных задач: управление объектами AD, аудит, инвентарь ПО/оборудования, работа с инцидентами, запуск и контроль автоматизаций (n8n), формирование отчетов.

## 2. Вход и общая навигация

### 2.1 Вход
- Страница входа: `/login`.
- Используется стандартная форма логина/пароля.
- Кнопка «Forgot password» отключена.
- После успешной авторизации открывается дашборд (`/`).

Любой вошедший пользователь AD получает доступ на чтение. Прямым участникам группы домена `Domain Admins` дополнительно разрешены изменения объектов и административные функции. Другие DN групп и точные имена входа администратор может задать через `LDAP_ADMIN_GROUP_DNS` и `LDAP_ADMIN_USERS` в сервисе Directory. Читатель может просматривать дашборд, каталог, инвентаризацию, инциденты, отчёты и справку; элементы редактирования и массового выбора недоступны. Для сканирования WMI учётную запись инвентаризации нужно указать в `LDAP_WMI_READ_USERS`. После изменения роли необходимо войти заново.

Если при сканировании появляется `ConnectException` для `DIRECTORY_SERVICE`, сервис Directory недоступен по указанному адресу (для локального запуска обычно `http://localhost:8081`). Запустите Directory или исправьте URL. Инвентаризация повторяет временные попытки подключения; число попыток и задержка задаются через `DIRECTORY_AUTH_MAX_ATTEMPTS` и `DIRECTORY_AUTH_RETRY_DELAY_MS`.

### 2.2 Макет интерфейса
Интерфейс состоит из:
- левой вертикальной панели верхнего уровня (Dashboard, Management, Incidents, Automation, Inventory, Reports, Account, Settings);
- подменю выбранного раздела;
- рабочей области со страницей;
- верхней панели действий страницы (если страница поддерживает меню действий).

### 2.3 Общие паттерны работы
Во многих списках применяются одинаковые механики:
- фильтры (блок с полями + кнопки Search/Reset);
- таблица (Grid) с переходом в карточку по клику на строку;
- верхнее меню действий (обновить, создать, импорт, удалить и т.д.);
- модальные окна (Dialog) для ввода/редактирования;
- окна подтверждения (ConfirmDialog) для опасных операций.

## 3. Раздел Dashboard

### 3.1 Dashboard (`/`, `/dashboard`, `/domain/dashboard`)
Назначение: сводный обзор состояния AD.

Отображаются графики:
- общий summary по количеству объектов (Computers, Users, Groups, Printers, Contacts);
- срез по пользователям (всего, disabled, locked, expired, never expires);
- срез по компьютерам (всего, disabled, workstations, servers, domain controllers);
- срез по группам (всего, security, distribution, built-in).

На дашборде также отображаются карточки состояния домена, найденных проблем безопасности, состояния учётных записей и здоровья инвентаризации. В каждой карточке есть переход к подробной странице. Для сводки инвентаризации используется порог устаревания 30 дней.

### 3.2 Domain (`/domain/info`)
Назначение: информация о домене и контроллерах.

Содержимое:
- имя домена и DN;
- карточка Domain Controllers (ссылки на карточки компьютеров);
- карточка Details (forest/domain/DC functional level, SASL, LDAP versions, current time, max password age).

### 3.3 Audit (`/domain/audit`)
Страница показывает изменения AD за выбранный период. Доступны фильтры по имени объекта, DN и действию. Нажатие на строку открывает подробности доступных LDAP-метаданных. Источник аудита AD не содержит пользователя приложения и исторические значения «до/после».
Назначение: просмотр аудита изменений AD.

Фильтры:
- Date range (from/to),
- Action,
- (в коде предусмотрено поле Name).

Таблица:
- Name,
- Distinguished Name,
- Action,
- When changed.

### 3.4 Состояние домена (страница Domain)
На странице Domain (`/domain/info`) теперь также находятся оперативные проверки LDAP, обнаружения контроллеров домена, разрешения DNS, доступности SMB-порта для SYSVOL/NETLOGON, расхождения времени LDAP и сертификата LDAP при включённом SSL. Результат каждой проверки отображается отдельно; кнопка Refresh запускает проверки повторно.

### 3.5 Глобальный поиск (`/domain/search`)
Поиск пользователей, компьютеров, групп, контактов и принтеров выполняется по основным атрибутам каталога. Нажатие на строку результата открывает карточку найденного объекта.

## 4. Раздел Management

### 4.1 Containers (`/management/containers`)
Назначение: работа с объектами AD в выбранном контейнере.

Интерфейс:
- слева дерево контейнеров;
- справа список объектов контейнера (cn/type/description).

Действия верхнего меню:
- Refresh;
- New -> User / Computer / Group / Contact.

Переходы:
- клик по строке объекта открывает карточку детали (user/computer/group/printer/contact).

### 4.2 Users (`/management/users`)
Назначение: список пользователей AD.

Фильтры:
- `cn`;
- статусный фильтр (All/Disabled/Locked/Expired/Never expires).

В таблице синие иконки обозначают включённых пользователей, а серые — отключённые учетные записи.

Действия верхнего меню:
- Refresh;
- New (диалог создания пользователя);
- Import (импорт пользователей из CSV).

Массовые операции:
- установите флажки у нескольких пользователей в таблице;
- выберите `Включить выбранные` или `Отключить выбранные` в меню страницы;
- подтвердите операцию. Изменения применяются к выбранным пользователям текущей страницы и фиксируются в аудите каталога.

Переход:
- клик по пользователю -> `User Details`;
- мультивыбор выполняется чекбоксами.

#### Диалог New User
Поля:
- Container,
- Display name,
- First name / Initials / Last name,
- Account name,
- Password / Confirm password,
- флаги учетной записи (must change password, cannot change, never expires, disabled).

Особенности:
- используются шаблоны имени/логина и default password из настроек.

#### Диалог Import Users (CSV)
Функции:
- загрузка CSV,
- выбор контейнера,
- импорт пользователей пакетно,
- кнопка справки с переходом в wiki по шаблону CSV.

#### User Details (`/management/users/:id/details`)
Содержимое:
- общая информация пользователя,
- фото (avatar),
- блок Member Of (группы).

Действия:
- Update,
- Photo,
- Options (параметры учетной записи),
- Reset password,
- Delete (с подтверждением).

### 4.3 Computers (`/management/computers`)
Назначение: список компьютеров AD.

Фильтры:
- `cn`,
- доступность/состояние (через комбинированный фильтр).

В таблице синие иконки обозначают включённые компьютеры, а серые — отключённые.

Действия верхнего меню:
- Refresh,
- New (добавление компьютера),
- включить/отключить выбранные компьютеры,
- удалить выбранные компьютеры.

Для массовой операции отметьте строки чекбоксами и подтвердите действие. Один клик по строке открывает карточку компьютера.

Для выбранных компьютеров доступны команды добавления в группу и удаления из группы. В диалоге сначала выбирается целевая группа, затем операция подтверждается.

#### Computer Details (`/management/computers/:id/details`)
Содержимое:
- базовая информация (hostname, OS, version, service pack, IP, manufacturer, model, location),
- блок Member Of.

Действия:
- Update,
- Delete (подтверждение),
- Management (подменю):
  - Processes,
  - Services,
  - Events,
  - Software,
  - Hardware,
  - Performance,
  - Reboot (подтверждение),
  - Shutdown (подтверждение).

#### Processes (`/management/computers/:id/processes`)
- список процессов с фильтрами;
- окно деталей процесса;
- операция остановки процесса (из диалога);
- Refresh из меню страницы.

#### Services (`/management/computers/:id/services`)
- список служб с фильтрами;
- окно деталей службы;
- операции Start/Stop;
- Refresh.

#### Events (`/management/computers/:id/events`)
- фильтры: source, event type, date;
- список событий;
- диалог просмотра деталей события;
- Refresh.

#### Software (`/management/computers/:id/software`)
- список установленного ПО на выбранном компьютере;
- фильтры по имени/вендору.

#### Hardware (`/management/computers/:id/hardware`)
- карточки аппаратных сущностей (computer system, BIOS, baseboard, disk, processor, video, memory и т.д.);
- представление в табличном формате с вкладками.

#### Performance (`/management/computers/:id/performance`)
- страница производительности компьютера (системные метрики/статус).

### 4.4 Groups (`/management/groups`)
Назначение: список групп AD.

Фильтры:
- `cn`,
- условия доступности/типа (через фильтры страницы).

Действия:
- Refresh,
- New (создание группы),
- удалить выбранные группы.

Выбор выполняется чекбоксами; перед удалением показывается подтверждение, а результат содержит число успешно удалённых и не обработанных объектов.

Для пользователей аналогично доступны массовые команды добавления в группу и удаления из группы.

#### Диалог New Group
Поля:
- Container,
- Name,
- Description,
- Group scope (Global/Local/Universal),
- Group type (Security/Distribution).

#### Group Details (`/management/groups/:id/details`)
Содержимое:
- общая информация,
- group type,
- блоки membership (Member Of и состав участников).

Действия:
- Update,
- Delete (подтверждение).

### 4.5 Contacts (`/management/contacts`)
Назначение: список контактов AD.

Действия:
- Refresh,
- New (добавление контакта),
- удалить выбранные контакты.

#### Диалог New Contact
Поля:
- Container,
- Display name,
- First name,
- Initials,
- Last name.

#### Contact Details (`/management/contacts/:id/details`)
Содержимое:
- карточка контакта,
- контактные поля (company, title, email, phones).

Действия:
- Update,
- Delete (подтверждение).

### 4.6 Printers (`/management/printers`)
Назначение: список принтеров AD.

Фильтр:
- `cn`.

Переход:
- клик по принтеру -> карточка принтера.

В таблице можно выбрать несколько принтеров чекбоксами и удалить их одной подтверждённой операцией.

В списке объектов выбранного контейнера также доступно массовое удаление поддержанных типов (пользователи, компьютеры, группы, контакты и принтеры). Системные и неизвестные типы не удаляются массовой операцией.

Для выбранных объектов доступен массовый перенос в другой контейнер. Перед выполнением выбирается контейнер назначения и запрашивается подтверждение.

#### Printer Details (`/management/printers/:id/details`)
Действия:
- Delete (подтверждение).

### 7.5 Состояние инвентаризации (`/inventory/health`)

Доступны запуск полного или выборочного сканирования, отмена текущего запуска, повтор проверки компьютеров с ошибками, фильтр по имени и результату, история запусков и экспорт CSV. Клик по строке открывает карточку соответствующего компьютера.
Кнопка «Создать инцидент» фиксирует просроченное сканирование, имя компьютера и время последней проверки в контексте инцидента.

Расписание фоновой инвентаризации настраивается администратором в разделе Settings: укажите cron-выражение и включите расписание. `SCAN_CRON` используется как значение по умолчанию при запуске сервиса (один раз в сутки). В разделе Inventory → Лицензии ПО можно вести реестр лицензий, сроков действия и приобретённого количества. Таблица показывает фактическое число установок и статусы `Соответствует`, `Превышение` или `Истекла`.

## 8. Раздел Reports

### 8.1 Списки отчетов
- `/reports/users`
- `/reports/computers`
- `/reports/groups`

Каждая страница содержит список отчетов с названием и описанием.
По клику отчет открывается в режиме предпросмотра.

### 8.2 Preview (`/reports/report?entry=...&id=...`)
Назначение: генерация и просмотр PDF-отчета.

Особенности:
- отчет формируется на основе заданных фильтров и колонок;
- выводится встроенным PDF viewer;
- поддерживаются типовые преднастроенные отчеты (в т.ч. по отключенным, заблокированным, срокам пароля, серверам, контроллерам домена и т.п.).

### 8.3 Планировщик отчётов (`/reports/scheduled`)
Администратор может создать ежедневное или еженедельное расписание для отчёта пользователей, компьютеров, групп, принтеров или контактов. Доступны форматы PDF и CSV, переключатель активности и необязательные получатели email через запятую. Кнопка «Запустить сейчас» позволяет проверить расписание; файлы и последние 100 запусков сохраняются в каталоге данных планировщика. Отправка выполняется через необязательные SMTP-параметры (`MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_SMTP_AUTH`, `MAIL_SMTP_STARTTLS`).

### 8.4 Аудит безопасности (`/security/audit`)
Аудит проверяет стандартные атрибуты Active Directory и показывает защищённые группы и пользователей с `adminCount=1`, пользователей и компьютеры с SPN, а также пользователей без email или руководителя. Результаты требуют проверки по политике домена. Регистрация MFA не доступна через стандартные атрибуты AD и проверяется в поставщике удостоверений.
Кнопка «Создать инцидент» создаёт инцидент по найденной проблеме с привязкой к пользователю или компьютеру. Действие требует подтверждения, после чего запись появляется в разделе инцидентов.

На странице групп также доступен импорт CSV. Обязательные колонки: `name`, `scope` (`Local`, `Global` или `Universal`) и `type` (`Security` или `Distribution`); `description` необязательна. Строки проверяются до импорта, ошибочные остаются в таблице.

## 10. Раздел Settings

### 10.1 Settings (`/settings/settings`)
Секция Theme:
- переключение цветовой темы интерфейса.

Секция User Patterns:
- шаблон `Display Name` для автозаполнения новых пользователей;
- шаблон `Login`;
- default password для создания пользователей.

Секция Language:
- выбор языка интерфейса (`en`, `ru`, `de`, `fr`, `es`, `pt`, `zh`, `ja`).

Действие:
- Save (сохраняет настройки и показывает подтверждение).

### 10.2 Webhooks (`/settings/webhooks`)
Настройте исходящие HTTP-уведомления для событий инцидентов (`incident.created`, `incident.updated`, `incident.closed`) и изменений каталога (`user.created`, `user.updated`, `user.deleted`, `group.created`, `group.updated`, `group.deleted`). В каждый запрос добавляются заголовок события и подпись HMAC SHA-256 при заданном секрете. Неудачные запросы повторяются до трёх раз. Значение `*` в поле событий подписывает webhook на все текущие и будущие события.

### 10.3 API-токены (`/settings/api-tokens`)
Создавайте отдельные токены для интеграций, назначайте срок действия от 1 до 365 дней и выбирайте права: чтение или изменение объектов каталога, чтение инвентаризации, чтение или изменение инцидентов. Полный список активных и отозванных токенов виден в таблице. Новый секрет показывается только один раз; отозванный токен перестаёт приниматься всеми сервисами сразу.

### 10.4 About (`/settings/about`)
Служебная страница «О программе» с информацией о продукте/версии.

- reboot/shutdown компьютера.

## 12. Типовые пользовательские сценарии

### 12.1 Создание пользователя
1. Открыть `Management -> Users` или `Management -> Containers`.
2. Нажать `New User`.
3. Выбрать контейнер и заполнить обязательные поля.
4. Указать пароль и параметры учетной записи.
5. Нажать `Save`.

### 12.2 Импорт пользователей из CSV
1. `Management -> Users`.
2. Нажать `Import`.
3. Выбрать контейнер и загрузить CSV.
4. Проверить успешность загрузки.
5. Нажать `Import`.

### 12.3 Удаленное действие на компьютере
1. `Management -> Computers` -> открыть карточку ПК.
2. В меню `Management` выбрать нужную операцию:
   - просмотр процессов/служб/событий,
   - reboot/shutdown.
3. Подтвердить действие в диалоге.

### 12.4 Работа с инцидентом
1. Открыть `Incidents`.
2. Найти инцидент через фильтры severity/status.
3. Открыть строку инцидента.
4. Изменить severity/status и сохранить, либо закрыть инцидент.

### 12.5 Формирование отчета
1. Перейти в `Reports` и выбрать тип (Users/Computers/Groups).
2. Выбрать конкретный отчет.
3. Просмотреть сгенерированный PDF.

## 13. Ограничения и примечания эксплуатации
- Разделы `Incidents`, `Inventory`, `Automation` зависят от доступности соответствующих backend-сервисов; при недоступности показывается ошибка `service unavailable`.
- Часть действий открывает n8n в отдельной вкладке по адресу `http://localhost:5678`.
- Большинство страниц оптимизированы под адаптивный режим: фильтры сворачиваются в мобильном представлении.
